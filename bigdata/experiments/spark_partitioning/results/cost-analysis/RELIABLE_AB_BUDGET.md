# A/B 신뢰성 보강 실험 — 예산 제안

2026-11-24. 사용자 승인 전 비용 설계이며 EC2에서 실행하지 않았다.

권장 예산은 **10,000원**이다. 서울 On-Demand Head m7i.xlarge 1대,Worker m7i.large 2대,총 Executor4 Core,4파티션,gp3 80GB,공인 IPv4 1개를 유지한다. 1달러1,400원·VAT10% 가정 시 약787원/시간이다.

## 제안 범위

- A: 기사 ID Hash 기본 입력,중간 Task 비용 편향,심한 Task 비용 편향.
- B: 테마 ID Hash 기본 입력,중간 테마 비용 충돌,큰 테마 여러 개의 심한 Hash 충돌.
- 각 app3전략×3조건×30개 독립 입력 블록=270회,총540회.
- 두 시점의 세션으로 나눠 조건별15블록씩 측정한다. 같은 블록 안에서는 입력·시드·원본 함수·자원을 동일하게 유지하고 전략 순서만 무작위 교차한다.
- 워밍업 제외,보정/검증 데이터 분리,paired 차이·95% 구간,p50/p95,Task 부하·Shuffle·자원·정합성 검증을 유지한다.
- 가능하면 운영 배치의 읽기 전용 파티션/테마별 기사 수 및 후보 수 통계를 입력 분포에 반영한다. 운영 대표성을 확인하지 못하면 합성 조건에 한정해 결론낸다.
- 통합 C와Kafka/DB/HDFS/외부LLM 비용은 이번 범위에서 제외한다.

## 시간·비용

로컬 기반180회 심한 편향 외삽은0.701시간이다. 기본 배치 시간은 이전 전체 탐색 기반 A/B 외삽을4개 분포로 나눈0.552시간을 보수적 proxy로 사용했다(별도 Driver 기준군 비용도 일부 포함). 중간 편향은 아직 측정하지 않아 두 값의 중간인0.626시간을 계획 가정으로 썼다. 이 값들을 새540회 EC2 실측으로 표시하지 않는다.

EC2 연산 시간은 로컬 외삽의0.5~2배,첫 구축1.5시간·두 번째 세션 재개0.5시간·Quick/보정0.5시간·분석/회수0.5시간을 더해 약3.9~6.8시간으로 계획했다. 두 세션 사이에는 인스턴스를 정지한다.

|항목|추정|
|---|---:|
|인프라 실사용|약3,098~5,315원|
|예비비2,000원 포함|약5,098~7,315원|
|누적10시간 실행 비용+예비비|약9,865원|
|제안 승인 예산|10,000원|

가격 근거는 [새 AWS 공개 요금 응답](SKEW_PRICING_SNAPSHOT.json),[180회 상세 견적](SKEW_EC2_ESTIMATE.md),계산 값은 [JSON](RELIABLE_AB_BUDGET.json)에 보존했다. 시간 범위는 신뢰구간이나 청구액 보장이 아니다. 중지 상태에서도 EBS는 과금되므로 결과 회수 뒤 소유 스택만 제거한다. 두 세션 전체의 누적 실행 시간을 관리해야 하며 기존 OnBootSec watchdog을 재부팅마다10시간으로 재설정해 쓰면 안 된다.

현재 실행기는 기본720회와 편향180회를 지원한다. 제안한 중간 편향·540회 분할·세션 간 누적 예산 관리는 추가 구현/로컬 검증 후 EC2에서 실행해야 한다. 이 문서는 구현 완료나 사용자 승인을 뜻하지 않는다.

30회 반복만으로 신뢰성이 보장되지는 않는다. 입력 대표성·독립성·효과 크기·구간 폭을 함께 평가하며,구간이 넓으면 결론을 유보한다. 추가 비용이 필요하면 새 승인을 받는다.
