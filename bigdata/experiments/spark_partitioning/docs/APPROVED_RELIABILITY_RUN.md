# 승인된 A/B 540회 실행 계약

사용자는 2026-11-24 예산10,000원 제안에 동의하고 실행을 요청했다. 기존 운영 코드·데이터·AWS 자원은 변경하지 않고 새 실험 스택만 사용한다. A/B 독립 실험만 포함하며 통합 C는 제외한다.

## 입력과 배치

같은 반복 번호에서는 세 조건의 논리적 기사·임베딩·기사 수·총 연산량이 같다. A는 모든 테마500건씩 총4000건,후보 수200/100/50/10/150/80/30/20이다. B는450/400/350/300/150/150/100/100건,총2000건이다. B는 논리적 기사 ID와 임베딩을 유지하고 theme ID alias만 바꿔 Hash 충돌을 제어한다. 운영에서 관측한 분포가 아닌 합성 입력이다.

|조건|A 초기 입력|B 기본 Hash 결과|
|---|---|---|
|NATURAL|기사 ID xxhash64,추가 강제 배치 없음|8개 연속 ID에 시드 기반 테마 대응,표준 Hash|
|MODERATE|기사 수1000씩,후보 비교량137000/86000/56000/41000|기사 수850/650/300/200 형태의 테마 충돌|
|SKEW|기사 수1000씩,후보 비교량175000/90000/40000/15000|기사 수1500/200/150/150 형태의 큰 테마4개 충돌|

A 중간 편향은 테마당300건을 해당 고비용 그룹에,나머지200건을4개 파티션에50건씩 넣는다. Hash/배치의 실제 목적지를 반복마다 회전한다. 세 조건의 논리적 입력 SHA가 같음을 검사하고,조건 순서와 전략 순서를 무작위 교차한다.

## 반복과 세션

각 app3전략×3조건×30반복=270회,총540회다. 세션1은 전역 반복0~14,세션2는15~29다. 세션 사이 결과를 회수하고 세 인스턴스를 정지·재시작해 새 Spark/JVM/Python Worker 및 동일 워밍업으로 측정한다. 각 app의 Quick을 각 세션에 수행한다. B 비용 모델은 세션1의 독립 Executor 보정으로 확정한 모델을 세션2에도 동결해 사용한다.

세션 하나의15회 결과로 최적 전략을 확정하지 않는다. 두 세션을 합쳐 조건별30개 paired 블록의 p50/p95·표준편차·95% bootstrap 구간을 분석한다. 소표본이나 운영 대표성의 한계는 별도로 표시한다.

## 인프라·예산·보존

서울 같은 AZ,m7i.xlarge Head1대,m7i.large Worker2대. 두 Executor×2 Core,4파티션,heap/container/BLAS 설정은 로컬 계약과 같다. 전용 VPC/보안 그룹,Head 공인IP1개,private Worker,암호화gp3 80GB다. 실험용 새SSH키는 로컬에서 생성하고 공개키만 스택으로 import한다. 원래 운영 키·인스턴스를 재사용하지 않는다.

watchdog은 첫 구축의 절대 UTC 시각을 기준으로10시간에 같은 StackId의 노드만 정지한다. 재부팅 시 시간을 초기화하지 않는다. Quick 실제 시간으로 남은 시간을 재검사한다. 계획상10시간 비용+예비비2000원은 약9865원이다. 환율·VAT·실시간 청구와 차이가 있을 수 있어 중간 시간을 확인한다. 실패도 원시 결과를 회수하고,회수 성공 시 소유 스택만 삭제한다. 회수 실패 시 EBS를 보존하고 소유 노드만 정지한다.

실행기는 `infra/run_reliability.py`이며 기본 동작은 계획 출력이다. 실제 실행은 사용자 승인 범위에서 `--execute`로 수행한다. 로컬 검증과 EC2 Quick 통과 여부,실제540회 완료 여부는 원시 결과 및 검증 파일로 판단하며 이 문서 자체는 완료 증거가 아니다.
